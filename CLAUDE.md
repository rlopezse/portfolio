## What this is

A static personal portfolio site (Spanish-language) for Ronald López, deployed to Firebase Hosting. There is no build step, no package manager, and no JavaScript framework — just hand-written HTML and CSS served as-is.

## Commands

There is no build/lint/test tooling in this repo. Common workflows:

- **Preview locally**: open `index.html` directly in a browser, or serve the directory with any static file server (e.g. `python3 -m http.server`).
- **Deploy**: handled automatically by GitHub Actions on push to `main` (see below). Manual deploy from the CLI requires the Firebase CLI: `firebase deploy` (uses the `ronaldlz` project configured in `.firebaserc`).

## Architecture

- `index.html` — the single page of the site. All content lives here directly (no templating).
- `404.html` — Firebase's default not-found page (auto-generated boilerplate, not hand-customized).
- `css/reboot.css` — CSS reset/normalize, loaded first.
- `css/index.css` — site styles, loaded after the reset. Defines a design-token system as CSS custom properties on `:root` (grayscale palette, spacing, font sizes, radii, shadows, transitions, z-index, breakpoints) followed by component classes (`.container`, `.header_*`). New styles should reuse these tokens rather than hardcoding values.
- `firebase.json` — Firebase Hosting config; publishes the repo root (`public: ".""`) and ignores dotfiles/`node_modules`.
- `.firebaserc` — points at the Firebase project `ronaldlz`.

### Deployment flow

Two GitHub Actions workflows (auto-generated by the Firebase CLI, in `.github/workflows/`) handle deploys via `FirebaseExtended/action-hosting-deploy`:
- `firebase-hosting-merge.yml` — deploys to the live channel on every push to `main`.
- `firebase-hosting-pull-request.yml` — deploys a preview channel for PRs from within the same repo.

Both require the `FIREBASE_SERVICE_ACCOUNT_RONALDLZ` secret. Pushing to `main` deploys to production, so treat commits to `main` accordingly.
